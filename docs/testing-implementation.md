# План реализации и изменения существующих файлов

## 0. Baseline
Прочитать AGENTS, architecture, network-contract, verification, development-handoff. Запустить существующий Verify.ps1 (или -ChecksOnly отдельно), зафиксировать baseline. Проверить GameManagedDir/BepInExCoreDir и GameDirectory: текущий Install-TestPlugin.ps1 использует N:\Steam\steamapps\common\Casualties Unknown и steam://rungameid/4576490, не считать эти пути универсальными. Исследовать декомпиляцию и записать bindings. Не менять protocol snapshot logic без выявленного дефекта.

## 1. TestKit
Создать tests/CasualtiesCoop.TestKit/CasualtiesCoop.TestKit.csproj (netstandard2.1), перенести ManualClock и SimulatedTransport из NetworkChecks, сохранить тесты TransportChecks/HostItemChecks/GuestItemChecks/ItemChecks/RecoveryChecks/FluidChecks. Изменить NetworkChecks.csproj, Core.csproj и при необходимости Protocol.csproj friend assemblies. Проверить стабильную очередь, reconnect, reliable ordering, loss, duplicate, limits. Добавить host+3 guest scenario, реальный SessionPeers.AttachReceiver, production item sessions, независимые stores. Не создавать второй simulator.

## 2. Первый Unity vertical slice
Создать src/CasualtiesCoop.Testing (netstandard2.1, ссылки на plugin/Core/Protocol/TestKit и game refs с Private=false). Добавить минимальные internal seams в CoopPlugin/CoopRuntime и при необходимости SharedItemReplication/SharedItemHostScene для lifecycle, read-only probes и actor-aware routing; не менять SteamSessionTransport. Отдельные TestRuntime, TestWorldController, ItemTestAdapter, VirtualSessionCluster, ScenarioRunner, AssertionEngine, ReportWriter. Использовать SandboxScene; не создавать фиктивный SteamLobby. В первом срезе один host world + 2 guests, затем 3. Запустить smoke, catalog, concurrent-pickup. Проверить реальный host scene registration и деактивацию предмета, guest stores, решения, trace. Отдельный guest projection сценарий с настоящим Body; отдельный input-path сценарий с Harmony. Не заявлять coverage непроверенных путей.

## 3. Автоматизация
Создать scripts/Run-GameTests.ps1 с -Scenario, -All, -Seed, -GameDirectory, -DotnetPath, -GameManagedDir, -BepInExCoreDir, -TimeoutSeconds, -Visible, -HoldOnFailure, -NoBuild (только при проверке hashes). Использовать существующий Install-TestPlugin.ps1 для production DLL, расширить явным -IncludeTesting или отдельным installer; не включать Testing/TestKit по умолчанию. Проверить наличие BepInEx и отсутствие запущенной игры; backup/restore только изменяемых DLL, удалить тестовые DLL после автоматического прогона. Запуск через штатный Steam/direct path после проверки; захват PID только своего процесса, runId handshake, bounded wait, cleanup. Не завершать чужие процессы. Verify.ps1 сохраняет прежнее поведение и -ChecksOnly, добавить opt-in -GameTests с параметрами и ненулевым exit code. ArchitectureChecks проверяет release bundle не содержит Testing/TestKit и production не ссылается на них. Добавить artifacts/ в .gitignore, не коммитить логи и пользовательские данные. Обновить docs/verification.md и docs/development-handoff.md без потери старых инструкций. Не использовать dotnet test для существующих console checks: они запускаются dotnet run.

## 4. Наблюдение
Visible mode: обычное окно, camera framing, labels, overlay текущего шага, peer states, queue, assertions; hold-on-failure с timeout. Добавить screenshot на failure если доступен. Затем pause/step/slow mode; не блокировать Unity main thread, учитывать wall timeout. Auto работает без focus. Проверить оба режима.

## 5. Расширение после MVP
Реальные Body и программный input, ASCII карты и terrain, жидкости, состояние тела, мобы и AI. Использовать confirmed bindings, не писать повторную физику. Для каждой новой механики добавить независимый probe и сценарий: movement/ragdoll, pickup/drop, disconnect/rejoin, snapshot retry, fluid convergence, mob target/damage/death/loot. Если механика ещё не реплицируется — BLOCKED. Отдельно проверить 4 peers и несколько seed/network profiles, reset/restart. Не расширять API до десятков заглушек.

## Acceptance
Verify.ps1 PASS, TestKit shared by NetworkChecks and Testing, no production dependency on test assemblies, test mode does not create Steam lobby, smoke and concurrent-pickup run automatically and produce real reports, negative control FAIL, independent guest states, visible mode works or explicit BLOCKED with evidence, no user save changes, cleanup verified. Maintain docs/testing-progress.md with commands, evidence paths, coverage matrix, blockers and next steps. Do not mark Steam E2E PASS. If environment prevents game launch, complete feasible code/checks and report BLOCKED with exact reason, do not fake results.
