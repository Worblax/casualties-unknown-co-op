# Именованные сохранения кооперативных забегов

## Как хост переключается между командами

В меню **Co-op** есть два действия.

- **Новый забег.** Хост задаёт название, создаёт комнату и собирает команду. При подтверждённом старте мод закрепляет состав и выдаёт забегу постоянный ID. Одна компания может хранить несколько забегов, в том числе с одинаковыми названиями.
- **Продолжить забег.** Хост выбирает запись по названию, составу, слою и дате последней контрольной точки. Список отсортирован по дате. Мод создаёт частную комнату для выбранного сохранения и показывает, кого ждёт. Персонажи, сложность и опции берутся из выбранного забега. Участники сверяют параметры и подтверждают готовность, затем хост запускает загрузку.

Например, хост и Аня сохранились перед слоем 5. Затем хост начал другой забег с Ильёй и сохранился перед слоем 3. В следующий вечер хост выбирает первую запись, приглашает Аню и продолжает со слоя 5 с её персонажем и вещами. Запись второго забега по-прежнему открывается со слоя 3.

Если кто-то из сохранённого состава отсутствует, кнопка **Начать** недоступна и комната показывает, кого ждёт. Порядок входа и смена ника не меняют место. В другом забеге тот же SteamID может обозначать другого персонажа с отдельным инвентарём. Изменение обязательного состава проводится отдельным подтверждаемым действием по [правилу исключения](coop-plan.md#именованные-сохранения-забегов).

## Забег, контрольная точка и комната

| Идентификатор | Срок жизни и назначение |
| --- | --- |
| `RunId` | Постоянный ID забега. Определяет его каталог и состав вместе со SteamID создателя. Два забега одного состава имеют разные ID. |
| `CheckpointRevision` | Номер последней записанной контрольной точки внутри `RunId`. Лобби закрепляет выбранную ревизию до готовности всей команды. |
| `SessionId` | Новый ID при каждом запуске сохранения. К нему привязаны Steam-комната, игровые сообщения и запросы живого переподключения. |
| SteamID участника | Ключ его места внутри `RunId`. Персонаж и подтверждённое состояние этого места берутся из контрольной точки. |

Сохранения лежат у хоста в каталоге мода `CasualtiesCoop/Runs/<HostSteamId>/<RunId>/` внутри `Application.persistentDataPath`. Список читается из каталогов забегов. Ванильный `SaveSystem` работает с одним `save.sv` и расходует его при загрузке. Кооперативное продолжение читает собственный снимок, который доступен после каждого открытия. Гости получают нужные данные по P2P. [Разбор ванильного сохранения](assembly-findings.md#жизненный-цикл-слоя-и-сохранение)

## Запись на границе слоя

1. Когда переход одобрен для всей команды, хост может выбрать **Сохранить и выйти**. Пока снимок создаётся, хост фиксирует границу принятых операций с вещами, состоянием тел и переходом. Гости видят «Сохраняем забег». Счётчики глубины, правила перехода и результаты возрождения применяются к снимку один раз.
2. Контрольная точка описывает вход в следующий слой. В неё входят номер слоя и цикл, параметры генерации и прогресса, закреплённые настройки, состояния тел всех участников, предметы с их ID и расположением, включая содержимое контейнеров и экипировку, сюжетный груз и подтверждённые результаты розыгрыша вещей. Предметы остаются только у тех владельцев, которых подтвердил хост. Хост генерирует начальный мир следующего слоя и передаёт гостям его состояние при загрузке. [Разбор перехода между слоями](assembly-findings.md#жизненный-цикл-слоя-и-сохранение)
3. Снимок новой ревизии записывается отдельным файлом в том же каталоге. Хост сбрасывает буфер записи на диск и проверяет целостность перед атомарной заменой ссылки на текущую ревизию в записи забега. Она содержит версию формата, слой для меню, размер и контрольную сумму снимка. Предыдущая успешно записанная ревизия остаётся доступна для восстановления записи. Незавершённый файл игнорируется. Успешная запись одного `RunId` меняет только его каталог.
4. Хост завершает комнату после подтверждения записи. При ошибке записи остаётся предыдущая контрольная точка. Хост видит причину и может повторить попытку с тем же состоянием перехода. Запись без контрольной точки помечена в списке. При гибели команды возможность открыть последнюю точку определяется настройкой этого забега. При гибели до первой точки продолжение недоступно.

## Загрузка и возврат игрока

1. Выбранные `RunId` и `CheckpointRevision` входят в план запуска новой комнаты. Хост проверяет версию и целостность снимка, своё владение записью, SteamID обязательного состава и совместимость сборок. Если запись недоступна, меню указывает конкретную причину и позволяет вернуться к списку забегов.
2. Хост поднимает следующий слой из сохранённых параметров, восстанавливает тела и вещи и передаёт гостям общий исходный мир и состояние их мест. Ввод включается после подтверждения загрузки от закреплённого состава. При сбое загрузки команда возвращается в комнату, а выбранная запись остаётся доступной для повторной попытки.
3. Если после старта отключился гость, он возвращается в текущий `SessionId` и получает текущее состояние от хоста. Если игра хоста закрылась, новая комната открывается через **Продолжить забег** с последней записанной контрольной точки выбранного `RunId`. [Проект живого переподключения](reconnection.md)

## Проверки после реализации

| Сценарий | Ожидаемый результат |
| --- | --- |
| Три сохранения, два разных состава, два забега с одним составом | Хост по очереди открывает все три. Совпадают слой, настройки, персонажи и вещи выбранного забега. Названия и порядок входа роли в выборе места не играют. |
| Один SteamID играет в двух забегах разными персонажами, меняет ник | В каждой комнате загружается персонаж и инвентарь из её записи. |
| Отключить хоста во время записи и при загрузке | После прерванной записи доступна последняя целая контрольная точка. Повторная загрузка сохраняет ту же ревизию и состояние инвентаря. |
| Гость вышел после запуска и вернулся, затем хост открыл другой забег | Живой возврат работает в текущей комнате. Старое приглашение не даёт места в новом забеге. |
| Участник отсутствует, контрольная точка несовместима или повреждена | Запуск останавливается с понятным статусом. Остальные записи доступны. |

Статус на 0.1.14 — проект. Каталог, сохранение общего слоя и загрузка команды ещё не реализованы. Песочница продолжает быть режимом проверки сетевых механик.
