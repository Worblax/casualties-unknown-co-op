# Проверенные привязки игрового стенда

Сигнатуры сверены с локальной `CasualtiesUnknown_Data/Managed/Assembly-CSharp.dll` через `ilspycmd -t`. SHA-256 `48C7F2296FC4A659FAAE3B1822884CA5B7FF73D6767EF159E6A6C2BC0B2D38F1`. Игровые проверки запускаются через штатный Steam-клиент и BepInEx 5.4.23.5.

| Компонент | Ванильный путь и наблюдение |
| --- | --- |
| Sandbox | `PreRunScript.StartTutorial()`, `TutorialHandler.StartCourse<SandboxCourse>()`, production `SandboxScene.Tick()`. |
| Каталог предметов | `Item.GlobalItems` перечисляет определения. `Resources.Load<GameObject>(id)` проверяет конкретный prefab на Item, Rigidbody2D и Collider2D. Для сети применяется production `SharedItemObjects.Supports`. Каталог различает декларации и реально проверенные prefabs. |
| Каталог мира | `WorldGeneration.GetBlockInfo(ushort)` используется для кодов 0..255. Типы жидкости берутся из таблицы `FluidManager` и доступных индексов частиц, названия воды и магмы сверены с `LiquidName`. Папка `Special/Characters` загружается целевым запросом, Body даёт `charType` для нативной фабрики. |
| Каталог мобов | Обнаружение уже загруженных prefab с `BuildingEntity` и проверенным компонентом AI, целевая проверка пути из `CaveTickSpawner.SpawnSpiders()` и дополнительные пробы по запросу. Весь корень Resources не загружается. Исполненный игровой AI — `cavetick`. |
| Body | `PlayerCamera.SpawnCharacter(int)` инстанцирует персонажа, только ванильный `PlayerCamera.Awake` назначает `main.body`. Подготовка физиологии выполняется после `Body.Start`, который задаёт начальные значения. Снимок читает `brainHealth`, `hunger`, `thirst`, `stamina`, `temperature`, `bloodVolume` и состояние конечностей. |
| Движение и приседание | Тестовые Harmony prefixes для конкретных Body выставляют `moveDir` перед `Body.FixedUpdate` и `crouching` перед `Body.Update`. Нативный код рассчитывает силу, ограничения скорости, коллайдер и анимацию. `character.speed` задаёт потолок `Body.maxSpeed`. Телепорт `character.place` предназначен для подготовки. |
| Прыжок и ragdoll | `Body.Jump()` проверяет опору, применяет собственную скорость, эффект и расход выносливости. Метод меняет `PlayerCamera.main.wantsJumpInput`, тестовый вызов восстанавливает этот флаг синхронно. `Body.Ragdoll()` проверяется через `standing`. |
| Инвентарь | `Body.PickUpItem(Item, int, bool)` с `force:false`, `Body.ThrowItem(float)` из активной руки, проверка `Body.GetItem(int)` и `HoldingItem`. В автономной локальной проверке дополнительный Body выполняет действия над отдельным нативным предметом. Сетевая операция удалённого участника сохраняет production-деактивацию авторитетного объекта. |
| Terrain | `WorldGeneration.SetBlock/GetBlock`, `DamageBlock(Vector2Int,float,bool,bool,bool)`, `GetBlockDamage`, `BlockDamage.UpdateSprite/DestroySprite`. Виртуальные гости используют production `TerrainDamageReplication.Receive/Tick`, отличаясь выбранной проекцией. Только назначенный Unity-гость изменяет видимый мир при получении. |
| Жидкости | `FluidManager.SetLiquid/GetLiquid`, нативное течение после `WorldGeneration.DamageBlock`. При `liquidPushing` нативный `FluidManager.IncrMove` создаёт `WaterPusher`. Тест наблюдает изменение компоненты скорости в `OnTriggerStay2D` и дальнейшее смещение предмета вдоль вектора потока. |
| Цель моба | Тестовый Harmony hook наблюдает результат настоящего `Physics2D.OverlapCircle(Vector2,float,int)` внутри `SpiderHandler.Update`. Учитывается запись AI в `target`, а принадлежность коллайдера определяется по Body или Limb. Проверяется выбор конкретного нативного Body, включая последующий выбор другого тела. |
| Эффект когтей и спирт | Сценарии проверяют входящий `ClawAnim` и отдельную гостевую проекцию `alcohol` в слоте и после броска. Полный сетевой путь от реального взмаха либо консольной выдачи требует независимых Steam-клиентов. |

Переподключение стенда использует события `SessionPeers`, production `GuestItemSession.ResumeAfterOffer` и реальные кадры снимка. Виртуальный transport подаёт подтверждённый номер операции из хоста через тестовую границу. Полный handshake `WorldSession.Recovery`, независимые сцены Unity, сетевой перенос предмета течением и репликация мобов остаются `BLOCKED` в этом окружении. Несколько настоящих Body находятся в одном мире. Полный ввод дополнительного тела, включая UI-подбор мышью и радиальное меню, остаётся BLOCKED: PlayerCamera выполняет эти операции для своего единственного body и общего интерфейса. Стенд вызывает подтверждённые методы самого Body и оставляет PlayerCamera.main.body у исходного персонажа.

Тестовые Harmony-привязки устанавливаются при `--coop-test`. Скрипт проверяет уникальный ID процесса, сохраняет игровые DLL и возвращает предыдущий комплект после теста. `isolation.json` проверяет хеши `save.sv`, `settings.json` и восстановление ключей `tutorial` и `lastchar`. Оригинальные DLL игры служат эталоном сборки. См. [фактические прогоны](testing-progress.md).
