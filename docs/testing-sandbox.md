# Архитектура игрового полигона

## Цель и границы
Один запущенный Unity player, настоящий SandboxCourse, до четырёх участников (хост + три гостя), независимые сетевые сессии и сериализованные кадры. Не обходить Steam/DRM. Отдельный тестовый BepInEx-плагин CasualtiesCoop.Testing, opt-in через --coop-test. Production не ссылается на Testing или TestKit. Допустим узкий внутренний lifecycle seam и InternalsVisibleTo; не открывать произвольный доступ к состоянию. Тестовый плагин не запускает Steam lobby. Если запуск через Steam не передаёт аргументы, использовать одноразовый локальный manifest с nonce и сроком действия, только при установленном тестовом плагине.

## Уровни доказательства
CORE: настоящие HostItemSession/GuestItemSession, независимые реестры, IItemWorld fixture. UNITY_HOST: настоящий авторитетный мир и SharedItemHostScene, сетевые запросы виртуальных гостей. UNITY_GUEST: отдельная проверка production SharedItemProjection и SharedItemInventory с реальным Body и входящими кадрами; не применять гостевые проекции к авторитетному предмету. UNITY_ACTORS: несколько настоящих Body для физики/AI и локальных действий, только после проверки ванильных singleton. STEAM_E2E: отдельные процессы/аккаунты, локально BLOCKED. Отдельно указывать, какие компоненты реально задействованы. Нельзя считать Core-only гостя полноценным Unity-клиентом.

## Композиция
Переиспользовать SandboxScene.Enter/Tick/Dispose; SandboxSessionController зависит от SteamLobby и при выходе из комнаты возвращает в меню, поэтому не использовать фиктивный lobby. В CoopRuntime добавить узкий opt-in режим, взаимоисключающий обычный runtime: отключить SteamLobbyStartup/menu/lobby ticks в тестовом режиме, подключить lifecycle тестового мира, save suppression, SceneLoaded, Tick и TickPresentation. CoopPlugin владеет Harmony и runInBackground; не устанавливать production patches повторно. CoopRuntime.ActiveWorld используется SharedItemHooks и другими патчами: обеспечить правильную маршрутизацию только к соответствующему миру/актору, не подменять глобальную ссылку на каждый кадр. Если первый срез работает непосредственно с SharedItemHostScene, явно указать, что WorldSession и Harmony input path ещё не проверены. При необходимости узкий seam для production hook dispatch; не допускать рекурсии при применении авторитетных изменений.

## Общий TestKit
Перенести существующие tests/CasualtiesCoop.NetworkChecks/SimulatedTransport.cs (включает SimulatedNetwork, NetworkProfile, NetworkFault) и ManualClock.cs в tests/CasualtiesCoop.TestKit, netstandard2.1. Заменить PriorityQueue совместимой стабильной очередью (time, order), Random.NextSingle на совместимый генератор; проверить воспроизводимость и старые TransportChecks. Не менять надёжную FIFO семантику, копирование byte[], queue limit и отбрасывание пакетов старого Link после reconnect. Добавить bounded delivery per pump и trace, валидировать finite/nonnegative параметры. Внутренние единицы времени существующего NetworkProfile — секунды, JSON — миллисекунды. В Unity clock продвигается по unscaled deltaTime с ограниченным бюджетом; пауза наблюдателя останавливает сценарий и виртуальную сеть согласованно, не обещать детерминированную физику. Не использовать Thread.Sleep в Unity. Существующие проверки net10.0 ссылаются на TestKit. Core/Protocol при необходимости friend assemblies; не делать всё public. Проверить отсутствие зависимостей TestKit от Unity/Steam и production от TestKit/Testing в ArchitectureChecks.

## Участники и объекты
Один RoomLaunchPlan на сценарий, уникальный Guid, уникальные synthetic ulong transport addresses в LaunchPlayer.SteamId (legacy wire field), ParticipantId через SessionPeers. Не менять wire только ради тестов. Каждый endpoint имеет отдельный SessionPeers и receiver через AttachReceiver; хост/гости получают только сериализованные кадры. Использовать HostItemSession и GuestItemSession, guest.Tick/TrySubmit/Receive, host.Receive/TickSnapshots. Гостевые реестры не разделяют mutable references. Сначала host + 2 guests, затем host + 3. Синхронизировать после регистрации предметов, ждать Synced и отсутствия Pending.

SharedItemHostScene сейчас для remote pickup деактивирует Item, а не кладёт его в Body. Это production-семантика, не дефект теста. Проверять host registry, отсутствие активного world item и независимые guest stores; фактический remote inventory проверять отдельным UNITY_GUEST сценарием через production projection. Не класть тот же авторитетный Item в гостевой Body. RemoteCharacterView — визуальная реплика без полноценного Body; настоящих тестовых акторов создавать отдельным подтверждённым ванильным путём. Для multi-actor действий изучить PlayerCamera.main.body, Body lifecycle, input/AI, global lists и inventory callbacks. Если действие требует singleton, не подменять его на время coroutine; документировать ограничение и использовать безопасный узкий адаптер либо BLOCKED. Тестовые акторы не должны случайно попасть в production item discovery/репликацию как дополнительные предметы.

## Lifecycle и безопасность
Создавать мир через SandboxScene, ждать CourseLoaded и реальные условия готовности. Изолировать saves, PlayerPrefs, achievements и любые checkpoint writes; существующий SaveSystem.SaveGame patch недостаточен как доказательство полной изоляции. Исследовать все пути записи, при невозможности изоляции не запускать разрушительный сценарий. Сохранять/восстанавливать настройки и исходные DLL при установке, не изменять оригинальные game DLL. Сценарий по умолчанию в свежем процессе; reset in-process только после теста очистки глобальных списков, subscriptions, coroutines, actors, timers и endpoints. Не убивать чужой процесс. Cleanup в finally. Watchdog с wall-clock timeout вне Unity, ограничение размеров сценария/trace/очередей.

## Наблюдение
--coop-test-view visible|auto; visible показывает обычное игровое окно, камеру на тестовую область, labels actor/peer, overlay scenario/step/seed, network queue, pending, owner/revision, статус assertions. Опционально step mode и slow motion, pause/resume/next через локальный UI или ограниченный IPC позже. Автоматический режим не требует focus, keyboard, screenshots; не обещать -batchmode/-nographics до проверки packaged player. --coop-test-hold-on-failure оставляет окно и снимок на ограниченное время; watchdog учитывает явную паузу. Камера/overlay не меняют gameplay и результаты; замедление фиксировать в отчёте. Скриншоты на failure опциональны, использовать существующий Test-GameWindow.ps1 если подходит. Не выдавать наблюдение за проверку независимых клиентских миров.
