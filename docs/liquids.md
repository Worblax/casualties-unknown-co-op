# Жидкости в локальной сборке

Разбор тел методов `Assembly-CSharp.dll` для сборки из [README](README.md). В игре одна система хранит жидкость в клетках мира, другая хранит смеси в миллилитрах. Подбор жидкости, питьё, лечение и крафт соединяют эти системы.

## Жидкость в мире

`WorldGeneration` выделяет `FluidManager.main.fluid = new byte[width, height]` при создании слоя. В клетке хранится один тип, без частичного заполнения.

| Байт | Тип в мире | ID при наполнении ёмкости |
| --- | --- | --- |
| 0 | Пустая клетка | У словаря есть запись `water`, но автозаполнение требует байт больше нуля |
| 1 | Вода | `groundwater` |
| 2 | Светящиеся водоросли | `lumalgae` |
| 3 | Нефть | `oil` |
| 4 | Сок | `sap` |
| 5 | Грязная вода | `dirtywater` |
| 6 | Магма | Пустой ID, ёмкость её не принимает |
| 7 | Красная жижа | `redsludge` |

- `FluidManager.StartFill → FloodFillDown` заполняет ограниченную область по горизонтали и вниз. Твёрдый блок или другая жидкость останавливают обход. При превышении лимита заполнение пропускается целиком.
- `FixedUpdate → SimulationStep → SimulationRangeIndex` сканирует полосы высотой 16 клеток около `PlayerCamera.main`. Это запись на месте с обменом клеток, приоритетом вниз, случайным выбором стороны, если обе свободны, и превращением пары 1/2 в две клетки типа 2 при вертикальном контакте. У нижней границы клетки удаляются. Порядок обхода и состояние соседей влияют на результат.
- `RenderFluids` обновляет частицы по локальному прямоугольнику примерно ±64 клетки раз в 0,1 с незамедленного времени. Отрисовку можно оставить локальной после того, как сетевой клиент получает состояние клеток.
- При `liquidPushing` метод `IncrMove` периодически создаёт `WaterPusher`. Триггер толкает физические объекты, а шкалу потери равновесия и переход в ragdoll сейчас применяет только к `PlayerCamera.main.body`. Для кооператива здесь нужен участник по коллайдеру, с учётом того, попало ли в поток обычное тело или конечность.
- `LiquidAffect.FixedUpdate` применяет сопротивление и плавучесть к телу, частям тела и предметам. У воды есть эффект намокания и очистки с записью грязной воды обратно в клетку. Магма повреждает конечности и экипировку, уничтожает обычные предметы и может активировать криоядро. `Body.HandlePhysics` отдельно определяет погружение головы для физиологии. `Item.OnWillRenderObject` отмечает намокание предмета при видимости. Для оружия это существенно: намокание влияет на осечки.

### Записи в карту, которые важно покрыть

| Источник | Что меняет |
| --- | --- |
| `FluidManager` | Поток, заполнение, питьё из мира, очистка массива. Некоторые операции пишут прямо в массив. |
| `WaterContainerItem.Update` | Автозаполнение убирает клетку, если ёмкость приняла положительный объём. |
| `WorldGeneration` | Инициализирует массив, размещает лужи, добавляет жидкость из тайлов, очищает области и охлаждает магму. `GeothermalLavaCool` сейчас выбирает позиции около одного тела. |
| `LiquidFiller`, `GeyserScript`, `OilPipeScript`, `CrystalDripping`, `PusSackScript` | Заполняют или создают клетки, в том числе прямой записью в массив. |
| `LifepodPump`, `DryModifier`, `CustomItemBehaviour.CryoActivate` | Перекачивают жидкость, осушают мир или превращают магму в блок. |
| `TraderScript.OnWillRenderObject`, `LiquidAffect`, `Body` | Убирают клетку рядом с торговцем, загрязняют воду, охлаждают магму в особом состоянии персонажа. |

Перехват одного `SetLiquid` пропустит прямые записи, включая обмен в симуляции, гейзеры и трубы. Нужны либо учёт всех путей записи, либо сравнение состояний активных чанков. Второе удобно для первой проверки полноты, но его стоимость на больших слоях нужно измерить.

## Жидкость в предметах

`WaterContainerItem` хранит сериализуемый список `LiquidStack(liquidId, amount)`. Вместимость и автозаполнение задаёт `LiquidItemInfo`, эффекты и свойства — `Liquids.Registry → LiquidType`. `condition` ёмкости отражает долю заполнения. Порядок списка важен: расчёты списания индексные, а поиск подходящего ингредиента может зависеть от порядка.

### Как изменяется смесь

- **Автозаполнение.** `WaterContainerItem.Update` ищет клетку под ёмкостью с включённым `AutoFill`, если предмет вне обычного `Container`. Пробует принять до 200 мл. Даже если свободно меньше 200 мл, любое успешное поступление очищает всю клетку. Учитывать это как правило игры при проверках баланса объёма.
- **Питьё с земли.** `Body.HandlePhysics` накапливает время при удержании вниз без горизонтального движения. Через две секунды вызывает `FluidManager.DrinkLiquid`. Большинство пригодных типов расходуют клетку, но ветки нефти и магмы её не очищают. Для грязной воды есть отдельная логика фильтрации. Это отдельная операция со своим правилом, её нельзя моделировать обычным переливом.
- **Переливание.** Перетаскивание идёт через `Body.CombineItems`. Быстрый режим вызывает `CombineLiquids`, диалог сначала показывает объём и подтверждает его через `LiquidTransfer.Finish`. `CombineLiquids` повторно ограничивает объём свободным местом, рассчитывает пропорциональное списание каждого компонента, списывает из источника и добавляет в приёмник. Если ёмкость превысила допустимый вес сумки, её выгружает. Обновление обоих предметов и места назначения — одна операция.
- **Питьё, нанесение, инъекция.** `Drink`, `ApplyToLimb` и `Inject` считают порцию пропорционально смеси и выполняют обработчики компонентов. Нанесение учитывает разрешённый тип и протез. При инъекции штрафы смеси могут применяться и к компонентам с запретом лечебного эффекта. Смесь расходуется целиком по рассчитанной порции, включая компоненты, которые не дали целевого эффекта.
- **Списание по типу.** `CalculateDrainSingleLiquid` используют `RecipeItem.UseItem`, `BioTerminalScript` и отдельные медицинские предметы. `Drain` удаляет компоненты с остатком меньше 0,5 мл. Нельзя отправлять по сети только список объёмов по индексам: после другой операции эти индексы могут означать уже другие компоненты.
- **Крафт жидкостей.** `Recipe.TryMake` находит предметы в инвентаре и окрестности, затем расходует их и создаёт результат. `RecipeResult.SpawnResult` ищет ёмкость с одним компонентом нужного типа и достаточным местом или создаёт временную `craftingbottle`. При низком навыке результат может оказаться меньше или не появиться после расхода ингредиентов. Для общего мира расход, случайный исход и появление предмета должен определять один участник симуляции.
- **Особые операции.** Центрифуга в `Item.SetupItems` разливает отдельные компоненты во временные ёмкости с потерями, очищает исходную смесь и запускает таймер. `Item.DrawBlood` меняет состояние тела и содержимое ёмкости. Биотерминал расходует определённую жидкость и запускает изменение в мире. Эти пути следует проверять отдельно от обычного переливания.

## Предлагаемая модель сети

1. Хост ведёт каноническую сетку и симулирует объединение областей участников. При пересечении областей обновляет свою полосу только один раз за шаг. При разделении игроков продолжает симуляцию в обеих областях. Нужна граница с соседними клетками, чтобы состояние на стыке чанков влияло на течение.
2. При входе клиент получает снимок интересующих чанков, затем изменения с номером версии чанка и слоя. При пропуске изменений запрашивает снимок. Тайлы и жидкость связаны: разрушение блока меняет доступность течения, а охлаждение магмы меняет сразу обе карты. Такие изменения должны применяться согласованно. Для малых изменений сравнить списки клеток, для массовых — сжатые снимки. Формат и частоту выбрать после профилирования.
3. Хост разрешает запросы питья, наполнения и использования по ID игрока, предмета и клетки или конечности. Проверяет актуальность, доступность, объём и вместимость. Выполняет операцию один раз и подтверждает итог по всем зависимым объектам. Повтор запроса не должен снова расходовать порцию или применять эффект.
4. Клиент может показывать предварительный объём в UI и визуальные частицы. Локальная симуляция клиента не должна менять клетку, массу, влажность, здоровье или предмет до подтверждения. Если предсказание движения в жидкости понадобится, использовать полученную карту с коррекцией от хоста.

## Сценарии проверки

| Сценарий | Критерий |
| --- | --- |
| Игроки расходятся, затем возвращаются | Поток у гостя продолжается за пределами камеры хоста. После повторного входа в область у обоих одинаковый снимок чанка. |
| Разрушить перегородку между лужами | Течение пересекает границу чанка, контакт 1/2 даёт тип 2, а магма при охлаждении превращается в блок и исчезает как жидкость. |
| Два игрока используют одну клетку | Только один успешный расход, если клетка расходуемая. Ёмкость со свободным местом меньше 200 мл воспроизводит ванильное округление на уровне клетки. |
| Перелить смесь при почти полной ёмкости | Совпадает состав обоих предметов, учитывается отсечение остатка меньше 0,5 мл. Перегруженная ёмкость выгружается один раз. |
| Крафт и медицинское применение из одной ёмкости | Порядок определяется хостом. Нет отрицательного остатка, второго применения эффекта или выдачи результата из уже потраченной жидкости. |
| Игрок, оружие и предмет попадают в поток | Участники видят одинаковые последствия толчка и падения. Намокание влияет на оружие у владельца, магма уничтожает предмет один раз. |
| Переход слоя при незавершённом запросе | Старое действие не изменяет новую карту или вновь созданный предмет. |
